# FLPATH-5050 deterministic fake-model replay

This is a TG-S1 experiment, not production ATG code. It checks one stable path
through a pinned Java 21/Quarkus fixture: submit a transfer request, then assert
its status and response fields. The fixed fake-model response is stored beside
the replay case. No model endpoint, credential, contract change, or production
import is involved.

The plan is labeled `synthetic_replay_input`; it does not represent an actual
human approval. The replay writes the generated Java test into a fresh copy of
the supplied fixture and records input, fixture-tree, model-response, and test
content digests. It rejects paths outside `src/test/java`, mismatched fixture
metadata, weak assertions, and reuse of an output directory. The `execute`
stage remains `not_run` in the deterministic record. The native Maven result is
recorded separately because replay-test success is not application-test
execution evidence.

## Replay checks

Run the tests with Python 3.11 or newer from the ATG repository root:

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 -m unittest discover -s tests/replay -p 'test_*.py' -v
```

On a host without Python 3.11, use a network-disabled Python container:

```sh
podman run --rm --network=none --read-only --tmpfs /tmp \
  --cap-drop=all --security-opt=no-new-privileges \
  -v "$PWD:/workspace:ro,Z" -w /workspace \
  -e PYTHONDONTWRITEBYTECODE=1 -e PYTHONPATH=src \
  docker.io/library/python:3.11-slim \
  python -m unittest discover -s tests/replay -p 'test_*.py' -v
```

Generate the test into a new, disposable copy of the Java fixture:

```sh
python3 experiments/harness/fake_model_replay.py \
  --fixture-root /path/to/java-analysis-adapter/spike/java21-quarkus \
  --output-root /tmp/flpath-5050-generated-fixture \
  --report experiments/harness/results/fake-model-replay.json
```

The test source is generated by a deterministic recorded response. This proves
replay stability and the basic output gate, not model quality, vulnerability
remediation, or the complete ATG lifecycle. Warm Maven dependencies separately,
then run the generated test offline. `results/fake-model-replay.json` records the
generation replay; `results/quarkus-transfer-execution.json` records the native
test result and limitations. The first offline attempt can reveal dependencies
that Maven's `dependency:go-offline` did not cache; do not count setup failures
as behavior-test failures.

## Scope and follow-up

The deterministic replay lives under `experiments/harness/` and
`tests/replay/`. It does not add a provider SDK, call a real model, implement
human checkpoints, modify the Quarkus source repository, or prove a CVE fix.
Broader candidate comparison remains follow-up work for FLPATH-5050.

## Candidate-neutral foundation check

For FLPATH-5050, give each candidate agent the exact text in
`fixtures/blank-user-objective.md`, then pass its new Java test file to the
evaluator. Keep the candidate outside this ATG repository so it cannot read
the reference test or mutation. Record the SHA-256 of that objective in the
invocation JSON. The evaluator does not call the agent or model. It verifies
the fixture's actual source-tree digest and installs the submitted test in two
disposable copies. For every candidate, it first packages each copy without
running tests, then runs only the candidate test class. Both `@QuarkusTest` and
`@QuarkusIntegrationTest` are allowed. The shared task defines a
`requestReference` different from the existing fixture test's `req-001`; it
does not require a random value on every run.

1. The unchanged Java 21/Quarkus fixture must pass.
2. A one-line mutation in `UserAuthPublicKey.doAuth` makes blank users pass
   authentication. The candidate test must fail with an assertion on this copy.

This is one known behavior check, not a CVE fix claim. A result is
`discriminates` only when both observations hold. Missing tests, compilation
errors, package failures, setup errors, and timeouts remain blocked or
inconclusive. A package failure cannot count as behavior detection. The output
JSON records candidate, tool/model/endpoint labels, test hash, verified fixture
hash, container image identity, separate package and test commands, exit codes,
logs, test counts, and limitations. It contains no API key.

Run on a host with Podman, the pinned Java fixture, and a warmed Maven cache:

```sh
python3 experiments/harness/candidate_evaluation.py \
  --candidate-test-file /path/to/TransferBlankUserTest.java \
  --candidate-test-path src/test/java/com/projectlightpath/fixture/TransferBlankUserTest.java \
  --candidate aider \
  --tool-version 0.86.2 \
  --model-id approved-model-id \
  --endpoint-id approved-endpoint-label \
  --invocation-record /path/to/redacted-invocation.json \
  --fixture-root /path/to/java-analysis-adapter/spike/java21-quarkus \
  --maven-cache /path/to/offline-maven-repository \
  --output-root /path/to/new-evaluation-output
```

The invocation JSON supplies the same candidate/tool/model/endpoint labels, a
redacted command argument list, prompt and configuration SHA-256 digests, and
optionally the candidate tool source revision. Keep the prompt and sanitized
configuration alongside the run for reproduction; never put credentials in the
record. A manually written control example uses
`fixtures/reference-invocation.json` with `model_id: none`. Use a fresh output
path per candidate. Each copy uses the same offline Maven sequence. This
example shows the manual reference class; the evaluator substitutes the
submitted class name:

```sh
mvn -o -B -ntp -Ptest -DskipTests package
mvn -o -B -ntp -Ptest -Dtest=TransferBlankUserTest -Dsurefire.failIfNoSpecifiedTests=true test
```

The Maven runs use the pinned Java 21 image with network disabled, a read-only
Maven cache, 2 CPUs, 2 GiB memory, 256 processes, and a 128 MiB per-file limit. The
writable workspace has no total disk quota; run tests from real agents only on
a disposable host or volume with a disk quota. Surefire XML is writable by
the candidate test, so treat this result as a review signal.
Results for different candidates are comparable only when they use the same
objective, fixture digest, mutation, and evaluation command.
